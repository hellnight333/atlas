Privacy

Atlas collects nothing by default, and operates no server that could receive your data.

What Atlas sends when you do nothing

Nothing. A fresh install has telemetry disabled and the update check disabled. No request is made to any Atlas-operated endpoint, because none exists.

There is no account, no sign-in and no sync. Atlas does not know who you are.

If you turn diagnostics on

ModeCollects
disabledNothing. The default
crash_onlyAnonymous crash reports
diagnosticsCrash reports plus version and platform

A crash report carries the exception type, the Atlas frames it passed through, your OS and architecture, and a random install id.

It deliberately excludes the exception message, because messages routinely embed file paths and your own text, and every stack frame outside the Atlas package, because those paths contain your username and project names.

This is enforced structurally: events are assembled from an allow-list of field names in the source, so a field cannot be collected until someone deliberately adds it. A deny-list would leak on the first oversight.

Where it goes

A local file you can read. Atlas runs no telemetry server, so there is nowhere for events to be sent.

The install id

Random, generated only when you enable telemetry, and not derived from your hardware, username or network. Disabling telemetry destroys it — re-enabling later produces a new one.

Model providers

Once real providers exist, prompts and assets you send to one go to that provider under your own key and their terms. Atlas is the client, not the counterparty. The offline profile refuses cloud providers outright.

Deleting everything

Uninstall, then delete the data folder. There is no copy anywhere else.
