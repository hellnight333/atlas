# Atlas User Flows

## 1. Flow Framework

Each flow is described using a common architecture:

- objective
- steps
- studios involved
- assets created
- agent participation
- decision points
- completion definition

## 2. Shared Stage Model

All flows use these canonical stages:

1. Intent Framing
2. Research and Evidence
3. Concept Design
4. Production Build
5. Quality Review
6. Publishing and Distribution
7. Retrospective and Memory Capture

## 3. Flow: Idea -> YouTube Video

Objective:

- transform a topic idea into a published, audience-ready video package

Steps:

1. capture topic, target audience, and success metric
2. research references and competitor framing
3. define angle, hook, and narrative structure
4. draft script and shot plan
5. create supporting visual assets and metadata
6. run quality checklist (clarity, pacing, claims, branding)
7. prepare publication package (title, description, tags, thumbnail set)
8. publish and record performance baseline

Studios involved:

- Research
- Video
- Image
- Publishing

Assets created:

- topic brief
- evidence notes
- script
- shot list
- visual kit
- thumbnail options
- publishing metadata bundle
- post-publish report seed

Agent participation:

- research synthesis assistant
- narrative variant assistant
- quality-check assistant
- metadata optimization assistant

Decision points:

- select strategic angle
- approve script version
- approve visual direction
- approve publish package

Completion definition:

- publish package delivered and baseline metrics captured in Activity/Memory

## 4. Flow: Idea -> SaaS

Objective:

- convert a product idea into a validated SaaS launch specification and execution roadmap

Steps:

1. define problem, audience, and value hypothesis
2. map competitor and substitute landscape
3. formulate product concept and differentiators
4. design user journey and feature priorities
5. define go-to-market narrative and launch plan
6. generate execution artifacts for implementation teams
7. run feasibility and risk review
8. publish project operating brief

Studios involved:

- Research
- Product workspace context
- Assets
- Publishing

Assets created:

- problem statement
- customer profile map
- competitive matrix
- product requirement narrative
- prioritized feature map
- launch strategy brief
- execution checklist pack

Agent participation:

- market scan assistant
- requirements structuring assistant
- risk-analysis assistant
- roadmap coherence assistant

Decision points:

- proceed/no-go after research confidence threshold
- MVP boundary definition
- launch scope and sequencing approval

Completion definition:

- implementation-ready product package with clear scope and launch narrative

## 8. Flow: Idea -> Research Paper

Objective:

- transform a research question into a submission-ready paper package

Steps:

1. frame research question and scope boundaries
2. conduct literature and evidence survey
3. synthesize themes, gaps, and hypotheses
4. outline methodology and argument structure
5. draft full manuscript sections
6. perform citation, logic, and quality review
7. generate submission checklist and abstract variants
8. publish final paper package and archival memory

Studios involved:

- Research
- Assets
- Publishing

Assets created:

- question brief
- literature map
- evidence table
- argument outline
- manuscript drafts
- citation package
- submission checklist

Agent participation:

- literature clustering assistant
- argument integrity assistant
- citation consistency assistant
- abstract optimization assistant

Decision points:

- hypothesis lock
- methodology confidence check
- draft acceptance for submission

Completion definition:

- submission-ready manuscript with traceable evidence package

## 9. Cross-Flow Decision Governance

Decision points are categorized:

- Directional: choose strategic path
- Quality: verify output standard
- Scope: constrain or expand effort
- Publish: approve external release

Each decision records:

- chosen option
- rejected options
- rationale
- downstream implications

## 10. Flow Reuse and Templates

Atlas supports converting successful flows into reusable templates containing:

- stage scaffold
- default assets
- role assignments
- quality gates
- publish checklist

Templates accelerate repeatable outcomes while preserving project-specific adaptation.

## 11. Flow Success Metrics

A flow is high-quality when it demonstrates:

- short time-to-first-draft
- high completion rate
- low avoidable rework
- clear decision traceability
- reusable outputs and process memory
