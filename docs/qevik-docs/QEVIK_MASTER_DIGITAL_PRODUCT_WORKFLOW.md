# QEVIK — MASTER DIGITAL PRODUCT & GROWTH WORKFLOW

## Research → Intelligence → Opportunity → Design → Demo → Media → Website → App → Commerce → Growth → Outreach

**Purpose:** Make Qevik a repeatable digital-product factory rather than a website-audit/demo generator.

---

## 0. Core principle

Qevik must not operate as:

> Find something wrong with a website and make a prettier website.

It should operate as:

> **Understand the business → understand its digital presence → identify evidence-backed opportunities → design the right digital product → build a convincing demonstration → verify it → create commercial assets → present a truthful sales proposition.**

A website may be the answer. It may also be:

- multi-page website
- ecommerce
- booking/order/quotation system
- CRM
- lead-generation system
- B2B portal
- customer portal
- marketplace
- mobile app
- PWA
- AI assistant
- content/SEO system
- marketing automation
- media/content factory
- 3D/interactive experience
- Amazon/Noon commerce operation
- advertising/content system

Never force every business into the same solution.

# 3. Technical website health

Measure, do not guess.

Check:

- HTTP status / redirects / TLS
- page speed
- Core Web Vitals where measurable
- LCP / CLS / INP
- image size and formats
- lazy loading
- JavaScript/console errors
- failed network requests
- broken links/assets
- mobile layout
- overflow
- accessibility basics
- keyboard/focus
- forms and validation
- phone/email/WhatsApp links
- social links
- maps
- embedded videos
- language/RTL
- cookie/privacy behaviour

Classify:

- FAST
- NORMAL
- SLOW
- UNAVAILABLE
- NOT_VERIFIED

Never call a slow site “broken”.

# 9. Opportunity evidence rules

Each opportunity must contain:

- evidence
- problem
- user
- commercial value
- complexity
- confidence
- Qevik product type
- priority

Evidence:

- CONFIRMED_PRESENT
- CONFIRMED_ABSENT
- NOT_VERIFIED
- REFUTED

Only confirmed evidence may establish a factual weakness.

Example:

> **Quote experience**
>
> The business already accepts enquiries, but the current journey requires several manual steps.
>
> Opportunity: a guided brief collecting occasion, guest range, date, service style and requirements before WhatsApp/email handoff.
>
> Benefit: lower friction while preserving bespoke quoting.

# 35. Critical constraint

Optimize for commercial usefulness, not technical novelty.

3D is useful when it demonstrates a capability.

An app is useful when the business model justifies an app.

A CRM is useful when there is a real sales workflow.

Amazon automation is useful when there is an ecommerce business.

AI is useful when it solves a measurable problem.

Do not build technology merely because Qevik can build it.

# 37. Definition of success

Qevik succeeds when it can take an unfamiliar business and answer:

> **What is this company, how strong is its current digital operation, where are the real opportunities, what product should we build, why would it matter, and can we demonstrate it convincingly without lying?**

Websites, apps, CRM, ecommerce, media, Amazon, Noon, ads, video, SEO and 3D then become capabilities of that system.
