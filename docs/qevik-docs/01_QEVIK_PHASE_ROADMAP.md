# P1 — EXECUTION FOUNDATION

## P1.2 — Recommendation + CapabilityOffer

Bridge **Opportunity → Recommendation → executable capability**.

Recommendation should explain:
- opportunity/evidence;
- expected benefit;
- capability;
- inputs;
- approval;
- execution cost;
- credit/plan implications;
- QA;
- measurement.

Reuse existing Opportunity and CapabilitySpec/Registry. Do not create duplicates.

**Done:** a real opportunity can produce an executable recommendation.

## P1.3 — AHS END-TO-END SLICE

Prove:

**Research → Evidence → Opportunity → Recommendation → Approval → Job → Execution → Asset → QA → READY_TO_PUBLISH**

Do not publish externally in this first slice.

Use an evidence-backed AHS opportunity such as the buried portfolio/contact-friction class.

**Done:** a real research-derived opportunity reaches READY_TO_PUBLISH with provenance.

## P1.4 — Measurement

Build reusable:
- baseline;
- intervention;
- measurement window;
- observed result;
- attribution confidence;
- evidence.

**Done:** the AHS slice has a measurable baseline and can record an outcome.

## P1.5 — 0→100 ROADMAP

Generate:
- prioritized tasks;
- dependencies;
- 10/30/90-day views;
- 0→100 progress;
- next action;
- owner;
- evidence;
- expected outcome;
- measurement.

Include CUSTOMER_TASK and QEVIK_TASK.

**Done:** a website/project can produce a non-generic next-step plan.

## P1.6 — CUSTOMER PORTAL

Start read-only where possible.

Surfaces:
business, audit, evidence, opportunities, recommendations, roadmap, jobs, assets, approvals, reports, measurement.

**Done:** a customer understands current state and next steps.

## P1.7 — CREDITS / PLANS

Reuse QuotaLedger and reserve-before-act.

Support architecture for:
- List;
- Pro;
- Advanced;
- Enterprise.

Define credit-consuming actions, included quotas, limits, reserve/spend/release and usage history.

No billing-provider connection until explicitly authorized.

**Done:** credit enforcement works without a parallel ledger.
