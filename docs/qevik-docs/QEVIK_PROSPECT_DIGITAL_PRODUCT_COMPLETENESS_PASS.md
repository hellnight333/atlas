# QEVIK — PROSPECT DIGITAL PRODUCT COMPLETENESS + UX + OPPORTUNITY PASS

## Purpose

The current AHS concept is much better visually and is now grounded in the real business. However, the workflow is still too focused on “make a better website”.

Qevik sells **digital products built around a business**.

That can mean a website, bilingual experience, booking flow, quotation tool, gallery, catalogue, customer portal, dashboard, mobile web app, configurator, estimator, recruitment platform, e-commerce experience, loyalty system, campaign, game, AI-assisted workflow, or a combination.

This phase must therefore evaluate every prospect on two separate dimensions:

1. **Website / experience quality**
2. **Missing digital-product opportunities**

Do not turn this into generic business consulting.

---

# 1. SOURCE AUDIT BEFORE DESIGN

Before designing any prospect demo:

- Visit the official website.
- Inspect all relevant public pages.
- Inspect navigation and footer.
- Inspect About, Services, Products and Contact.
- Inspect social links.
- Inspect forms and conversion paths.
- Inspect mobile behaviour.
- Inspect Arabic / RTL.
- Inspect blog/news/resources.
- Inspect privacy/terms where public.
- Inventory images and media.
- Record what the business actually does.
- Record what the website already does well.
- Record genuine weaknesses.
- Record potential digital products.

Record evidence and `source_checked_at`.

Never invent missing information.

- QA status

The outreach system can then select the most relevant product.

---

# 53. ONE PROSPECT, MULTIPLE PRODUCTS

Do not assume one prospect can only have one demo.

Example:

```text
AHS
├── Website concept
├── Event Brief Builder
├── Gallery experience
├── Arabic experience
└── Mobile event planner
```

But do not overwhelm the customer.

The salesperson should select the strongest demonstration.

---

# 54. OUTREACH SHOULD NEVER SAY "WE BUILT YOUR APP" IF IT IS A CONCEPT

Use precise language:

```text
I put together a concept for how this could work.
```

or:

```text
I built a working prototype around this workflow.
```

Only say:

```text
We built your app
```

when that is actually true and approved.

---

# 55. CUSTOMER MEDIA PERMISSION SHOULD BE A HARD GATE

If:

`permission = no`

do not use customer-owned images in a public demo.

If:

`permission = approved`

allow the media workspace to make those assets available to builds.

If permission is revoked:

- remove from future builds
- retain original provenance records
- do not silently reuse

---

# 56. QUICK MEDIA REPLACEMENT

The operator workflow should be:

```text
Customer approves photos
        ↓
Tick "Permission to use original images"
        ↓
Select photos
        ↓
Apply to demo
        ↓
Rebuild / refresh
        ↓
QA
```

No need to manually rewrite the site.

Support:

- crop
- focal point
- aspect ratio
- compression
- colour correction
- enhancement
- background treatment
- generation of supplementary visuals

Always preserve the source asset.

---

# 57. GENERATED IMAGE PROVIDER

Do not lock the architecture to a specific image provider.

The image service should eventually support:

```text
OpenAI image generation
Local image generation
Other provider
```

The first implementation can use whichever provider is currently available.

But the product interface should ask for:

```text
Generate supplementary visual
```

rather than exposing provider-specific assumptions everywhere.

---

# 58. GENERATED IMAGE SAFETY / HONESTY

Never use generated people/events/products in a way that implies:

- they are real customers
- the image is an actual AHS event
- the business produced the pictured event
- the pictured venue is theirs

Label generated concept imagery internally and, where necessary, visibly.

# 60. AHS FINAL REVIEW QUESTIONS

### Source

- Did we inspect their blog?

- Does RTL work?

### Content

- Are articles useful?
- Are images relevant?

### Product

- Is there an opportunity beyond the website?

# 61. IMPORTANT COMMERCIAL PRINCIPLE

Do not optimize the demo to make the prospect think:

> “Nice website. We could copy some of this.”

Optimize it so they think:

> “They understood what we do, they found a better digital way to present or operate it, and I couldn't build this myself just by looking at the idea.”

That means:

- real research
- real source content
- real interaction
- real UX
- real product thinking
- real implementation

The competitive advantage is not the screenshot.

It is the **understanding + product + execution** behind it.
