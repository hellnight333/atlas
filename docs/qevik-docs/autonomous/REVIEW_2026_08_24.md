# Architecture and business review — 24 August 2026

Findings from this session's work, each classified **NOW**, **NEXT**, **LATER**
or **REJECT**. Every one is grounded in something checked, not in an impression;
where a finding was checked and turned out not to be a problem, that is recorded
too, because "we looked and it was fine" is a different state from "we did not
look".

## NOW — done in this session

### 1. The repository did not contain the credential vault

Two commits reported adding it. Both added only its tests. `.gitignore` carried
a generic `credentials/` rule — sensible, aimed at directories where secrets get
stored — that also matched a source package sharing the name. `git add -A` on a
parent path says nothing about an ignored child, so there was no signal at any
point: the files were on disk, imports resolved, the suite was green, and the
commit reported success.

It would have surfaced when somebody cloned the repository and 707 lines of
tests failed to import.

**Fixed.** The source package is re-included specifically, and
`test_repository_completeness.py` now asks `git ls-files` rather than the
filesystem — because the filesystem is exactly what makes this invisible from
inside a test run. It carries its own negative control.

**The general lesson, which outlives this instance:** a green suite is evidence
about the working copy, not about a clone. Any rule naming a directory
(`keys/`, `certs/`, `private/`) is a rule that can swallow a package.

### 2. `?sort=confidence` returned a 500 on the prospects list

`_card` assigned `confidence` twice in one dict literal — the scoring
component's points, then the level string. Python keeps the last. The points
were computed and discarded, and the sort table did `-c["confidence"]`, which is
a `TypeError` on a string.

Ruff had been reporting this as F601 the whole time, inside a 22-error baseline
recorded as "the baseline". **That is how a live bug hides behind a number that
never moves.**

**Fixed**, with a structural test: no dict literal anywhere in the kernel may
assign a string key twice. Exactly one existed across the kernel, and it was
this one.

### 3. Multi-page generation shipped the defect it sells against

The first implementation split on three invented thresholds and produced a
222-character contact page — below `THIN_CONTENT_CHARS`, the threshold Atlas
applies to *strangers'* websites when selling them a fix.

**Fixed** by deriving the rule instead of inventing it: a page is kept only if,
once rendered, it clears the detector's own threshold, imported and never
restated. Tightening the detector now tightens the generator in the same commit.

## NEXT — real, not urgent, and cheap relative to their risk

(#5 moved here on inspection, then fixed, because it was smaller than the cost
of carrying it.)

### 4. `claim()` is not atomic across processes, and the worker is now a process

Honestly documented in `mission/service.py` and `mission/timeline.py`: folding a
file cannot compare-and-set, so two workers can claim one mission. That was
academic while there was no worker binary. `infra/mission_worker.py` now exists,
takes `--name`, and is obviously runnable twice.

The gap between "documented limitation" and "foot-gun" is the existence of the
second copy. Needs a Postgres row with `SELECT … FOR UPDATE SKIP LOCKED`, which
is a genuine schema addition rather than a refactor.

*Until then:* run one. The limitation is stated in both modules and the daemon's
docstring.

### 5. Six B023 closures in `control/sales.py` were correct only by accident

Lambdas in the prospect detail route captured `folded`, `findings` and
`business` from the enclosing `for folded in everything:` loop. They were
correct **only because `_safe()` invokes them immediately**. The day `_safe` gains a queue, a
cache or a thread — all plausible, since it exists to degrade a panel rather
than a page — every prospect would render the last iteration's data, and it
would read as a data bug rather than a scoping one.

**Fixed in this session** — bound at definition (`lambda f=folded: …`). It was
a small change and it removes a trap, so deferring it would have cost more in
carrying it than in doing it.

### 6. The mypy baseline is 135, and it is mostly *not* hidden bugs

Checked rather than assumed, because finding #2 made it reasonable to expect
more of the same:

| Code | Count | What it actually is |
|---|---:|---|
| `no-untyped-def` | 46 | Missing annotations. Cheap, low risk, no bugs. |
| `arg-type` | 24 | Mixed. |
| `union-attr` | 20 | Sampled two; both false positives. |
| `operator` | 11 | Sampled two; both false positives. |
| everything else | 34 | Not sampled. |

Two `union-attr`/`operator` findings were traced to source
(`measurement/models.py:306`, `outreach/demos.py:650`). Both are genuinely
guarded — through a property and through a compound early-return that mypy
cannot narrow. **Neither is a bug.**

So the conclusion is the opposite of finding #2's: the lint baseline was hiding
a live defect, and the type baseline mostly is not. 82 of the 135 sit in three
files (`website/repository.py`, `opportunity/repository.py`,
`measurement/models.py`); annotating those three would move the number a long
way without touching behaviour.

**The number itself is still the problem.** A baseline that only ever holds
steady is technical debt with a reassuring name, and it is where #2 lived. Worth
driving down — but as maintenance, not as a bug hunt.

The lint baseline went the other way in this session: 22 → 0. Two of those 22
were live defects (#2, #5) and two more were tests weakened by what they
tolerated — `pytest.raises(Exception)`, which passes on a `KeyError` from a
broken store just as happily as on the auth refusal it means to assert, and a
helper whose docstring described shaping data through the real path while its
body returned its own argument, with no callers. **Zero is now the baseline, and
it should stay zero**, because the whole argument for the number 22 was that
those were the errors not worth fixing, and two of them were a 500.

### 7. Every credential probe returns 501

`POST /api/credentials/{provider}/test` cannot test anything, for any provider,
because `app.state.credential_probes` is empty everywhere.

This is deliberate and correct — a probe that guessed would be worse than none,
and the route says so rather than showing a tick — but it means a stored
credential is `PENDING_CREDENTIAL` forever. One real probe per adapter-ready
provider (`qwen`, `anthropic`, `openai`) closes it.

### 8. Nothing turns a conversation into a mission

`POST /api/missions` accepts a title and a description. The chat intake that
produces them, persists the conversation, and attaches a plan for approval does
not exist. The mission lifecycle is complete on both ends and open in the
middle.

## LATER — blocked on things that are not code

### 9. Product B needs hosts, not modules

A coding-agent sandbox, a browser worker and an Iran-resident host are machines
to provision. The application-side contracts can be built ahead of them and
partly are; the workers cannot be written into existence.

Recorded in `ROADMAP_RECONCILIATION.md`. Nothing here is blocked on a decision
anybody has failed to make.

### 10. No deploy target beyond local

Publication architecture is complete — gate, bundle hash, approval fingerprint
over published bytes — and only a local filesystem target is connected. A public
URL with HTTPS verification is the last step of the website vertical, and it
needs a host and a DNS record.

## REJECT

### 11. Docs 11/11A — the media business

Implementing them inside this repository would put a YouTube media operation
inside a B2B evidence engine: different customers, different unit economics,
different failure modes, sharing a tenancy model and a timeline with neither.

Their own gap analysis lists legal entity, developer accounts and IP rights as
Tier 1. **None of that is code**, and none of it is unblocked by writing any.

### 12. Billing

Plans, credits and quota exist and are enforced. Money does not, deliberately.
Adding a payment integration before a customer has agreed a price would be
building the mechanism for a decision nobody has made.

## Checked and found fine

Recorded so the next reader does not re-derive them:

- **Tenant isolation across every customer read and both new writes.** Another
  tenant's resource is absent with an identical body to a missing one, on every
  route added this session.
- **No route returns a stored secret**, swept with a canary across every
  credential route including the error paths and a provider that echoes the key
  back.
- **The worker genuinely runs without the API.** Proven by subprocess, with the
  application object destroyed, not mocked.
- **Determinism survived the multi-page split.** Same content, same bytes.
