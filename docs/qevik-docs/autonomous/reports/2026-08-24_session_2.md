### Arabic — the offer with the most demand and no delivery

`website/arabic.py` and its executor. The design turns on one refusal: **Qevik
does not translate.** A machine translation of a business's own description of
itself is a claim about them, published in their name, in a language the person
approving it usually cannot read — silent, total, discovered from a phone call.

So it takes Arabic a person wrote, pairs it with the English, and drops anything
unpaired rather than leaving English inside an Arabic page. Three translated
sections ship as three sections. An AST walk asserts the module reaches for no
model, because a translation call added later would look like an improvement and
nobody reviewing the diff reads Arabic.

What it *does* build is the half that is engineering rather than authorship:
`dir="rtl"`, `lang="ar"`, the hreflang pair, the language switch, and phone
numbers held left-to-right inside right-to-left text — without which a number
renders reversed, the most visible defect on a badly built Arabic page.

### Enquiry — a form with nowhere to send is worse than no form

`website/enquiry.py` and its executor. Qevik has no SMTP credential and no host
that runs code, and "build it and wire it later" ships a form that discards every
enquiry while the visitor believes they made contact.

So the form works today, through `mailto:` and WhatsApp links composed on the
visitor's own device. `hosted_form_gap()` costs the upgrade — host, SMTP
credential, spam handling, a retention decision — so it is a known step rather
than a discovery.

### Three findings that came out of building them

**The executor registry had no contract.** `Executor` is `Callable[..., ...]`,
which says nothing about arguments, so both new capabilities registered cleanly
and failed at execution with a `TypeError` — after the roadmap offered the work
and the approval was granted, inside a `try/except` that records failures as
data. The convention is now `CALLING_CONVENTION`, checked against what
`service.py` actually passes by parsing it.

**An executor existing does not mean it can ever run.** Correctly aligned, Arabic
still refused: the service passes four arguments and none can carry
customer-supplied Arabic. The refusal was right; presenting the task as "Qevik
can do this" was not. `REQUIRES_CUSTOMER_INPUT` now gates executability, the same
shape as the earlier correction where an offer existing did not imply an
executor. Both move the same way: fewer things promised, each one true.

**`Prose` silently dropped its own provenance.** `Prose` has no `source` field —
that is `Fact`'s — and pydantic discarded the unknown keyword without complaint,
so the attribution the Arabic capability entirely rests on was being lost while
every test passed. `Prose` is now `extra="forbid"`, which immediately found every
other instance. In the module whose whole purpose is provenance, silently
accepting a misspelled provenance field is the worst available default.
