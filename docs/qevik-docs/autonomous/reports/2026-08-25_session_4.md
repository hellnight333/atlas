## What app.qevik.ai actually was

It resolves to real Cloudflare addresses (`104.21.30.175`, `172.67.173.123`), a
nonexistent subdomain correctly fails to resolve, and it serves the older **Qevik
Sales Intelligence** interface. So the domain is live and healthy.

Probing it, `/api/missions` returned **200** — which looks like the control plane
being live. It was the SPA fallback: `content-type: text/html`. The production
Caddyfile proxied `/auth/*`, `/control/*` and `/health` and nothing else, so
every control-plane call fell through to `try_files … /index.html`.

**A 200 that is the wrong document is worse than a 404**, because only the second
is obviously broken. Anything not checking content type — including a naive
health check — would have read that as the API working.

## The console

`apps/control/src/index.html`. One file, no build step, written to the CSP
already in the production Caddyfile rather than asking for it to be relaxed.

Thirteen surfaces: Dashboard, Roadmap, Mission Control, Chat, Human Actions,
Credentials, Models, Businesses, Publications, Measurements, Reports, History,
Settings. Responsive — the sidebar becomes a scrolling strip under 820px.

Two rules it is written to:

**No business logic.** Every number, status and decision comes from the kernel.
The page arranges what the API returns and sends back what somebody clicked. The
moment it decides whether a mission is really complete, there are two answers and
the one on screen is the untested one.

**Nothing executes from the browser.** Approving posts an approval and returns; a
worker elsewhere picks the mission up. The page must not quietly undo that by
driving a mission from a polling loop.

Details that follow from the kernel's own commitments: the mission lifecycle is
drawn as the sequence `ALLOWED` permits, so an operator sees how much is left
rather than one word; a cost the provider did not report renders `UNKNOWN`, never
zero; the session token lives in `sessionStorage`, not `localStorage`, which
outlives the tab on a shared machine.

## The acceptance test

`infra/run_console_acceptance.py` — a real uvicorn, a real socket, and the server
killed in the middle. **33 checks, all passing.**

```
1. shell loads unauthenticated · deep link serves the shell
2. all five API surfaces refuse without a session
3. sign in
4. thirteen surfaces answer · 16 integrations listed · no credential value returned
5. conversation → plan (a blocker, not an invention) → blocked plan refused
   → real plan approved → mission queued, not running
6. the server is killed                        <- the browser going away
7. the worker runs alone, with nothing serving HTTP
8. a NEW server: mission complete · committed · full lifecycle on the record
   · durable report · conversation intact · the typed sentence unchanged
```

A TestClient could not have tested this. It shares a process with the thing it
tests, so it cannot distinguish "the mission persisted" from "the object was
still in memory".

## Four real defects it found

**The worker wrote no reports.** Every runner script wrote one; the thing that
actually runs missions in production did not. The console correctly showed "no
report" because there was none. `mission_worker.py` now writes one per mission
and records the path on the mission.

**`AuthStore` could not run on sqlite** — three separate causes: `ADD COLUMN IF
NOT EXISTS` is a Postgres extension, and sqlite returns timestamps as the strings
it stored, breaking both `_to_user` and the session-expiry check on the hot path
of every authenticated request. Fixed; the auth stack now runs on a throwaway
file, which is what a local run, a developer machine and an acceptance test all
want.

**I over-exposed `/api/health`.** `test_the_public_path_list_is_short_and_harmless`
pins `PUBLIC_PATHS` exactly so that an unauthenticated route is a conscious
decision. It caught me adding one that reports whether the vault is sealed, which
components are absent and what claiming guarantees — deployment posture. It is
behind a session now; `/health` stays public and returns a status word. The
console's routes are a separate `CONSOLE_PATHS` set so the pin still means what
it says.

**A cached store cannot see a second writer.** The acceptance harness's
conversation store read once at construction, so the server never saw what the
script wrote. Now it re-reads — the same property `mission/timeline.py` has, for
the same reason.
