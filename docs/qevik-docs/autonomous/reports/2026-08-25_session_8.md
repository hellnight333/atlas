# Autonomous session — one credential boundary, and three honest non-answers

From `41a21fc`, 25 August 2026. Four items, of which one was a defect to fix,
one is blocked on an external dependency, and two were correctly answered by
**not** building something.

## 1. The vault path mismatch — fixed

The control plane wrote `<QEVIK_STATE>/vault.json`; the worker read
`<vault_root>/credentials.json`. The Credential Centre could show a credential
`CONNECTED` that the worker could not see.

**The fix I shipped last session was worse than the bug.** It accepted either
shape and fell back to whichever file existed. Two paths that usually agree
diverge the moment one is written, and nothing reports it — a fallback there
hides the ambiguity rather than removing it. That was the right thing to be told
about.

`credentials/location.py` is now the only module that names a credential file.
It returns **both** together, because they are one boundary: the vault holds the
secret, the timeline holds the record, and a process with only one finds
nothing. `paths_for()` takes the state *directory* and raises on a file, because
a function accepting both would be the fallback again. `QEVIK_VAULT` and
`--vault` are gone — each named a single file, leaving the other to be resolved
elsewhere.

Two source-reading tests keep it one: no caller may name a credential file, and
every caller must call `paths_for`. Both directions, because a file with no
literals and no credentials would pass the first check alone. The original bug
was two literals in two files that agreed on the day they were written.

Both processes now **log where they looked** at start-up. The failure was
invisible for as long as it was precisely because neither ever said which file
it was reading.

**Live: 16/16** — save through the Centre, restart the control plane, restart
the worker, same fingerprint and hint from the worker's own resolution, no
second store, no secret on disk.

## 2. Model-backed mission — still blocked, on the provider

The path is now completely wired, and the log reads in order:

    credentials: restored 1 record(s) from the timeline
    credentials: {'state': '/var/lib/qevik/control', 'vault': …, 'records': …}
    model registry: skipping qwen (INVALID_CREDENTIAL)
    no model is available for planning

The worker read the credential the Centre stored, through the canonical
boundary. The registry refused to turn a provider-rejected key into a model. The
worker refused to run rather than substituting the stub. The mission stayed
`queued` and untouched.

Every one of those is the designed behaviour, and none of it was weakened.

**The external dependency:** `QEVIK_DASHSCOPE_API_KEY` is the only provider
credential configured anywhere on the host — confirmed by enumerating every
`*_KEY`/`*_TOKEN`/`*_SECRET` in the live service environment — and DashScope
rejects it at the configured regional endpoint, at intl and at Beijing, so it is
not a region mismatch. The vault holds no other provider record.

## 3. Agent-to-agent persistence — not required, and guarded

`fabric/protocol.py` defines an `Exchange` and a `Conversation`. **Nothing on
the live path constructs one.** A mission runs single-agent:

    mission → scheduler → claim → worker → registry → adapter
    → tool contract → sandbox → evidence → report

No message passes between agents anywhere in it. Building storage for a type
nothing creates is work that ages without being exercised, so it was not built.

What *was* built is a tripwire. `test_agent_conversation_persistence.py` walks
the AST of every module that runs in production and fails the moment one
constructs an `Exchange`, naming the fold to use and saying not to invent a
second mechanism. It has its own negative controls: one proving the detector
fires on a real producer, one proving the guarded type still exists, and one
separating this from *user* chat — which is a different thing and **is**
persisted.

The point is not that the feature is unnecessary forever. It is that the day it
becomes necessary is now loud instead of silent.

## 4. Second worker — not added

One worker, empty queue, no throughput requirement. Two workers racing one
mission is already proven 7/7. A permanent second would be a number, not a
capability.
