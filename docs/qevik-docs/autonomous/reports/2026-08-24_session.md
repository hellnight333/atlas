## §18 — re-evaluation as a mission

The obvious implementation re-researches and overwrites, on the reasoning that
the newer engine knows more. That destroys the only thing a second look
produces — the difference — and gets one case dangerously wrong.

A feature that was confirmed and is now unverified is indistinguishable from a
decline unless the two are separated. Telling a customer their page speed got
worse when the crawler timed out is exactly the dishonesty the evidence
architecture exists to prevent.

So six change kinds split into two registries: `ABOUT_THE_BUSINESS`
(newly_observed, disappeared, contradicted) and `ABOUT_OUR_CHECKING`
(now_confirmed, now_unverified). The customer-facing statement never merges the
two clauses. Neither input is mutated — a delta is worthless if the baseline can
move — and the comparison is appended as its own event carrying `changes`, never
a replacement set of `observations`.

Run as a real mission on AHS through create → plan → approve → worktree → agent
→ acceptance → commit → report:

```
2 change(s) on the site itself; 2 change(s) in what we were able to check,
which is about our coverage rather than the business.

  On the site:    website  — → present   newly_observed
                  whatsapp not_found → present  contradicted
  In our coverage: ai_visibility — → unverified   now_unverified
                   page_speed  present → unverified  now_unverified
```

The mission folded back to `complete` from the on-disk timeline after the run.
Report: `2026-08-24_re-evaluate-ahs-against-the-current-engine_mission-9db5c0c5307f.md`.

## Mission control, and why the browser is not load-bearing

The tempting design lets the route that starts a mission also run it. That makes
the browser tab structural: close it, lose the network, or restart the API to
deploy, and a mission dies half-committed with a worktree behind it.

No handler in `mission/api.py` runs anything. Every write appends an event and
returns. A tripwire test reads the module for `Worker(`, `subprocess`,
`GitWorkspace` — because the docstring is exactly what stays true while the code
stops being.

**Proven, not asserted.** `test_mission_independence.py` submits and approves
over HTTP, destroys the application object, spawns `infra/mission_worker.py` as
a real subprocess with nothing serving HTTP, and builds a *new* application to
read `complete`. An in-process test asserting the worker was called would prove
the wiring and nothing about the independence.

Other decisions worth not re-deriving:

- Approve and cancel go through the same `ALLOWED` table the worker obeys.
- Cancel **refuses** while a worker holds the mission, and names the worker.
  Recording it cancelled while the agent is mid-write would show a cancelled
  mission that goes on committing.
- Costs never present a floor as a fact: unpriced calls are counted beside the
  total rather than folded in as zero, REPORTED and ESTIMATED never merge, mixed
  currencies are flagged instead of summed.
- `report_path` arrives on an event, and an event is data — resolved under the
  reports directory and refused if it escapes.
- The worker **refuses to run without a model**. `--agent fake` is typed by a
  person, never a fallback: a worker that silently substituted a stub would
  claim missions, commit files, write reports and mark everything complete, and
  every artefact would describe work no model ever did. Exit code 2, queued
  mission untouched.

## The credential centre

One door in, no door out. There is no route that returns a stored secret, in any
state, through any error path. The test sweeps a canary across every route
including the 409s, the validation errors, and a probe that echoes the key back
the way a real API's 400 does.

Storing is not connecting: a pasted key is `PENDING_CREDENTIAL` until something
tests it; a rotation drops the previous verification; a provider with no probe
returns 501 rather than a green tick *or* a red one. Writes need ADMIN; testing
needs only EXECUTE, so diagnosing does not require the scope that can replace
the key. A sealed vault refuses to store rather than degrading to plaintext.
Forgetting answers identically whether anything was there.

**No key was ever requested, pasted, hardcoded, logged, or committed.** The
staged modules were secret-scanned with the scanner negative-controlled against
a planted canary first — a silent scanner and a clean file look identical.

## Multi-page websites

The first version used three invented thresholds and shipped a 222-character
contact page: the exact `thin_content` defect Atlas detects on strangers' sites
and sells the fix for, on a customer's domain, under our name. It would have
read as an improvement in any test that asked only "did it render".

The rule is now derived. A page is kept only if, once rendered, it clears
`THIN_CONTENT_CHARS` — **imported from the detector, never restated** — and a
site splits only when at least two pages earn it. Tightening the detector now
tightens the generator in the same commit.

Home is never a stub: it carries in full whatever no page claimed and in brief
everything they did, with the phone number and email at full length, because
"click through for our number" is the friction the offer sells against. One
registry with a `brief` mode, not two parallel maps.

## Customer write routes

Two, deliberately. A customer may say they did their part, and may decide an
approval. Everything else stays a read, because everything else is work Qevik
owes them.

Proof is **established, never accepted**: `observed` runs the check, `approval`
reads the approval's own state rather than the id the caller typed, `attestation`
records whose word it is and is refused without a name. `verified_by_system` is
derived and has no field, so a customer cannot assert that Qevik checked
something Qevik never looked at. A Qevik task submitted for completion is
refused — the conversion of work-we-owe into work-they-did arrives as an
ordinary call with a valid task id.

## A live bug found in the accepted lint baseline

`?sort=confidence` on the prospects list returned a 500. `_card` assigned
`confidence` twice in one dict literal — the scoring component's points, then
the level string — and Python keeps the last, so the sort's `-c["confidence"]`
was negating a string.

Ruff had reported it as F601 the whole time, inside a 22-error baseline recorded
as "the baseline". **That is how a live bug hides behind a number that never
moves.**

So the baseline was cleared rather than preserved: **22 → 0**. Two of the 22 were
live defects; two more were tests weakened by what they tolerated
(`pytest.raises(Exception)`, and a helper whose docstring described work its body
did not do, with no callers). Zero should stay zero.

The mypy baseline was checked the same way and the conclusion is the opposite:
46 of 135 are missing annotations, and two sampled `union-attr`/`operator`
findings traced to genuinely guarded code mypy cannot narrow. It is maintenance,
not a bug hunt. See `REVIEW_2026_08_24.md` §6.
