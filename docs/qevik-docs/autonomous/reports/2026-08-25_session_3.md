# Autonomous session — measurement, delivery, and Qevik publishing itself

`b066bc8..f59411c`, two commits, 25 August 2026. Resume from `MASTER_STATE.md`.

## What was built

### Measurement sources — `measurement/providers.py`

Search Console and Analytics, on the `aivisibility` pattern: protocol, fixture
provider, `PendingCredentialProvider`, and the two real sources refusing by name.

Arranged around a distinction a metrics API makes easy to lose. **Zero is a
measurement; unavailable is our outage.** Search Console genuinely returns zero
clicks for a page nobody clicked. A refused request returns nothing. Recording
the second as zero manufactures a decline out of an authentication error, and the
customer reads "your clicks fell to zero" in a report they paid for. So
`Reading.value` is `None` when nothing was established, never `0.0`, and the
fixture preserves the same distinction rather than inventing plausible traffic.

`comparable()` refuses the three ways a comparison lies — different windows,
different sources, a ratio over too small a sample — and `change()` will not
state a delta it cannot defend. Windows never include today: both sources report
partial data for the current day, and a partial day against a whole one is a fall
that did not happen.

**The live calls are deliberately unwritten.** Search Console returns *no row*
for a query that matched nothing, so the naive implementation reports zero
impressions for a page it never asked about correctly. Written blind, that code
would look finished and encode the exact mistake the module exists to prevent.

### Publication boundary — `publication/targets.py`

Everything that can exist without a host: target protocol, a real `LocalTarget`,
a Cloudflare adapter, a DNS model, domain verification, deploy, rollback, status.

**No partial success.** A target writing four files of six and reporting success
leaves a live site half-replaced — worse than a failure, because the old page is
gone and nothing reports an error. `LocalTarget` stages and renames, so a failure
halfway leaves the previous version intact, and rollback restores it.

**Domain verification is a TXT record only the owner can create**, tokenised per
tenant so one tenant's proof cannot verify another's domain. Three outcomes stay
apart: present, absent, and *we could not look* — the last is `UNKNOWN`, because
publishing on our own outage and telling a customer their record is missing when
we never looked are the same error.

**`NOT_AUTHORISED` is not `FAILED`.** Everything was ready and nothing was sent.
A caller treating them alike retries something nobody agreed to.

`MissingCredential` and `MissingInfrastructure` are separate classes: collapsing
them makes provisioning a server look solvable by typing a password.

### Qevik publishes its own site

`infra/run_qevik_self_use.py` now runs the last step for real:

```
without authorisation : NOT_AUTHORISED (nothing written)
local target          : PUBLISHED -> index.html, robots.txt, sitemap.xml
cloudflare, unverified: FAILED — the domain is not verified (NOT_CHECKED)
domain proof required : TXT qevik.ai = qevik-site-verification=1dbfe61f…
cloudflare, verified  : FAILED — Add QEVIK_CLOUDFLARE_API_TOKEN
bundle identity       : 5421f3917b2eaf90… carried onto the deployment
```

An unverified domain stops a public publish *before* a missing credential is
reached — the right order, since a token would not make publishing to an unproven
domain acceptable.
