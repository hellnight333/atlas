# Autonomous session — two gates: the Credential Centre, and the fabric wired

From `05218a8`, 25 August 2026. Both gates verified against the **live** system
on qevik-core-01, not a TestClient.

## Gate 1 — the Credential Centre

Reported: Claude and Qwen stay `NOT_CONFIGURED` after Save; Save and Test do not
work. Two defects, one symptom. Full detail in `CREDENTIAL_CENTRE_FIX.md`.

**The vault persisted the secret and the record did not.**
`CredentialService._records` was a plain in-memory dict. Everything the Centre
reads — fingerprint, hint, verification result — lived only in the process, and
the service restarts on failure and on every deploy. Worse than a display bug:
the secret stayed in the vault, **unreachable and impossible to forget**,
because `forget()` looks the record up before dropping it.

The module docstring already promised "a place to store one that outlives the
session that entered it", and every sibling module — `publication`, `roadmap`,
`credits`, `aivisibility` — has a `to_event` *and* a `read` that folds it back.
`credentials` had `to_event`, no fold, and nothing appending. Designed, never
wired.

**No probes were registered at all.** `/test` answered 501 for every provider,
so a credential could never leave `PENDING_CREDENTIAL` — only a probe can move
it.

Fixed by following the existing pattern rather than inventing a store: `to_event`
made lossless, `restore()` folding latest-by-timestamp, a `FORGOTTEN` kind so a
destroyed credential is not resurrected, and one `_remember()` that updates the
dict *and* appends. Real probes now ship by default; none reads the provider's
body, because a provider that echoes the request echoes the header.

### Live verification — 20/20, on `tenant-qevik`

save → read → **restart** → read → test → **restart** → read → forget →
**restart**. A temporary operator was created with a password generated on the
server, never printed, and removed afterwards.

    qwen      -> INVALID_CREDENTIAL   DashScope rejected the credential
    anthropic -> INVALID_CREDENTIAL   Anthropic rejected the credential

`INVALID_CREDENTIAL` is the *correct* answer: it proves the probe made a real
authenticated call and the provider rejected a deliberately fake key. A
`CONNECTED` would have meant the probe was not really asking.

## Gate 2 — the fabric wired

Full detail in `FABRIC_WIRED.md`. The scheduler now decides dispatch order,
`PostgresClaims` decides who, `mission/adapter.py` joins the registry to the tool
contract and the sandbox, and `POST /api/missions/{id}/plan` gives the control
plane the planning step it never had — previously a mission could be submitted
and approved through the API but only *planned* through chat.

The model stays a proposer. The `/plan` route moves a mission to
`AWAITING_APPROVAL` and cannot queue anything; the scheduler reports it as
`WAITING` with `dispatchable=[]` until a person approves. That is asserted in
the run, not just documented.

`--require-atomic-claims` makes an unreachable claim database a **refusal to
start**, because the alternative is the worst failure available here: an operator
believes two workers are safe, both fall back to local claiming, and two commits
of the same change appear with no error anywhere.

### The acceptance mission

`self-check` — a real agent record, executor-backed, no credentials, no network,
no provider, no spend. Three declared steps, defined once so the plan a person
approves cannot drift from what runs. The third step runs `cat /etc/shadow` **as
root** and passes only if it fails: the containment is asserted by the mission
rather than assumed by the harness. It ran at `confinement=FULL`.

### End to end on qevik-core-01 — 27/27

Real server process, real worker process, real PostgreSQL, real bubblewrap, and
the control plane **killed** while the worker runs. Lifecycle recorded in full:
`draft → planning → awaiting_approval → queued → processing → testing →
reviewing → committing → complete`. Still complete after two restarts, still
pointing at its report.

### Two workers, one mission — 7/7

Exactly one claim, exactly one `processing` transition, exactly one commit.

## Five defects found by running it

Four of them only appeared on the real host.

| Where | What | Why it mattered |
|---|---|---|
| `credentials/service.py` | records in memory while the vault persisted | a saved key read back as NOT_CONFIGURED, its value orphaned in the vault |
| `qevik/app.py` | no probes registered | `/test` answered 501 for **every** provider |
| `mission/api.py` | reports resolved against the repository root, not the worker's | the report existed, the mission pointed at it, and the console said "no report" |
| `mission/gitspace.py` | committer identity taken from the host's global git config | the mission did all of its work and died at the last step with "Committer identity unknown" |
| `mission/worker.py` | `result.report` computed and never passed to `reports.write` | a report could say a mission succeeded without saying what was checked |

Plus one in a harness: the two-worker check asserted a *mechanism* — that the
loser logs "went to another worker" — when the loser is equally correct to never
have seen the mission queued. It now asserts the property: only one ran it.

## A mistake I made, and fixed

While setting up the claim database I reset the `qevik` PostgreSQL role's
password, which is the role `ATLAS_DATABASE_URL` uses. That broke authentication
for the live control plane for roughly two minutes. I restored it from the
configured URL — server-side, without printing it — restarted both services and
confirmed the database, both surfaces and both user accounts were intact. Noting
it because a report that only lists what went right is not a report.

## What remains genuinely unblocked

- **Rotate the two exposed keys** and enter them in the Centre. They will now
  persist, and Test will say whether they work.
- **`budgets.reserve()` from the worker.** The scheduler consults the tenant
  balance before dispatch; per-mission and per-agent allowances are not charged
  at execution time.
- **Set `QEVIK_CLAIMS_DSN` for the service.** The worker takes it; the control
  plane still reports `SINGLE_WORKER_ONLY`, honestly, until it is set.
- **A model-backed mission through the same path.** The wiring is
  agent-agnostic; `cli-implementer` additionally needs a credential.
- **`Conversation` persistence.** Designed to fold, no event kind writes it.
